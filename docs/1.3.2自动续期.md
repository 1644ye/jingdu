# 1.3.2 GitHub 登录自动续期

日期：2026-11-02。

## 升级后怎么用

直接覆盖安装，保留书籍、已登录账号和仓库。旧版只保存了访问令牌，没有刷新令牌；请分别进入书源、进度账号设置，用同一账号重新登录一次，以便获取续期凭据。原仓库选择保留。进度账号重新登录后，按现有流程确认并开启同步。

账号设置显示“已启用自动续期”后，后续请求会在令牌临近到期时刷新。正常续期不会改变仓库、取消下载、清除缓存或暂停同步。不自动过期的令牌也继续支持。

## 实现范围

- 登录时分别加密保存访问令牌、刷新令牌及两者到期时间。继续使用原 Android Keystore 密钥与设备偏好文件，不进入书库备份。
- 书源与同步各使用自己的 Client ID 和凭据，采用设备授权刷新，不保存 Client Secret 或私钥。
- 已知到期时间的访问令牌提前一分钟刷新；服务端返回 401 时刷新并最多重试一次。403、限流和其他错误不误当访问令牌过期。
- 统一应用于仓库列表、连接验证、目录和索引读取、书籍下载／更新、进度读取与写入。断点下载重试保留已下载片段和 Range 请求。
- 同一角色的并发刷新在进程内串行，刷新后一次保存新令牌对。退出或重新登录期间返回的旧刷新结果不会覆盖新登录。
- 网络错误保留原凭据，恢复网络可重试；刷新令牌已到期或被撤销时明确要求重新登录，保留仓库配置。不以自动续期代替用户撤销授权后的重新授权。

GitHub 当前规则：访问令牌通常 8 小时到期，刷新令牌 6 个月到期，成功刷新会轮换两者；设备授权获得的凭据刷新时不需要 Client Secret。[官方说明](https://docs.github.com/en/apps/creating-github-apps/authenticating-with-a-github-app/refreshing-user-access-tokens)

## 手机验收

1. 覆盖安装后检查旧书籍、阅读位置、账号与仓库仍在。
2. 书源和同步角色分别重新登录一次，确认状态显示“已启用自动续期”；确认同步仓库后开启同步。
3. 正常浏览、下载和同步；隔天再次使用，检查无需重新输入设备码即可完成操作。
4. 网络中断后重试，原书籍和仓库仍可用。
5. 在 GitHub 主动撤销授权后再次使用，应要求重新登录；重新授权后仍能选择原仓库。
6. 切换账号或退出后，旧请求不得恢复原账号的凭据；新账号按既有规则重新选择仓库。
