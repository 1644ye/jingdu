# 静读下一轮开发计划

日期：2026-11-01  
状态：待开发

本文件确定下一轮开发范围与验收要求，不代表功能已实现或测试通过。

## 1. 开发目标与边界

在现有 Android 阅读器上增加：

- GitHub 只读书库和真实目录层次浏览。
- `catalog.json` 索引及电脑端生成工具。
- 单本、多本、整目录选择下载及正文更新。
- GitHub 登录，以及手动更换书源账号、仓库。
- 阅读进度双向同步与多设备冲突处理。

继续保留本地 JSON 导入、离线阅读、标签、分组和备份功能。

**App 不得修改远端书源。** 不提供远端书籍上传、编辑、移动、重命名、删除或索引回写功能。书源维护通过 GitHub 网页或电脑 Git 完成。

第一版同时启用一个书源连接和一个进度同步连接，支持手动更换，不开发多书源聚合。笔记、划线、书签、个人标签和配色暂不纳入跨设备同步。

## 2. 仓库与权限设计

| 仓库 | 内容 | App 权限 |
| --- | --- | --- |
| 书源仓库 | 书籍 JSON、目录、`catalog.json` | 只读 |
| 独立私有同步仓库 | 各设备阅读进度 | 读写 |

两个角色不能配置为同一仓库。书源只读必须落实到授权权限，不能仅隐藏写入按钮。

书源连接与同步连接分别保存账号、仓库和授权状态。更换书源账号，不自动更换进度同步账号。

## 3. 手动更换书源账号和仓库

入口：**更多 → GitHub 连接 → 书源设置**。

必须区分：

- **登录账号**：提供访问权限的 GitHub 用户。
- **仓库所有者**：仓库地址中的个人或组织，可以与登录账号不同。

| 配置项 | 要求 |
| --- | --- |
| 登录账号 | 显示实际授权用户名，支持退出、重新登录和更换账号 |
| 仓库所有者 | 可手动填写个人或组织名称 |
| 仓库名称 | 可手动填写或从已授权仓库中选择 |
| 仓库地址 | 支持粘贴 GitHub 仓库 URL |
| 分支 | 默认使用仓库默认分支，允许更换 |
| 书源根目录 | 支持仓库根目录或指定子目录 |
| 索引路径 | 默认根目录下的 `catalog.json`，允许修改 |

提供“连接并保存”和“取消”。

切换规则：

1. 新配置连接成功后才替换旧配置；失败时保留旧连接。
2. 切换时取消旧连接尚未完成的刷新和下载，旧请求结果不得混入新页面。
3. 已下载书籍、个人标签和阅读记录保留，继续关联原书源。
4. 不因两个仓库存在同名或同 ID 书籍而自动合并。
5. 注销清除相应凭据与私有目录缓存，保留已导入的本地书籍。
6. 所有连接信息均可在 App 内更换，无需重新编译 APK。

## 4. catalog.json 与目录

推荐结构：

```text
catalog.json
books/
├─ 诗集/
│  └─ 唐诗/
│     └─ 李白.json
└─ 小说/
   └─ 古典/
      └─ 示例小说.json
```

索引格式：

```json
{
  "schemaVersion": 1,
  "libraryId": "personal-library",
  "books": [
    {
      "id": "libai-poems",
      "path": "books/诗集/唐诗/李白.json",
      "title": "李白诗选",
      "author": "李白",
      "type": "poetry",
      "tags": ["唐诗", "古典"],
      "bytes": 125600
    }
  ]
}
```

实施要求：

- 远程书库一本书对应一个 JSON；现有本地多书 JSON 导入继续支持。
- 路径相对书源根目录，按路径展示中文多级目录和面包屑导航。
- 正常书单从索引读取；真实目录读取用于目录浏览、核对及索引缺失时展示。
- 索引缺失或无效时明确提示，不把失败显示为空书库。
- 同一次索引读取与正文下载固定到相同仓库提交。
- 利用 GitHub 文件版本信息检查更新，不新增自定义摘要系统。
- 目录返回不完整时继续加载或明确提示，不能误报为完整书库。

提供电脑端生成脚本，扫描书籍、提取元数据、检查重复 ID 和无效文件后生成索引。由用户提交至 GitHub，第一版不强制接入 GitHub Actions。

## 5. 下载、更新和本地管理

支持单本、多本、整目录下载，并显示：未下载、下载中、已下载、有更新、失败。

下载可取消、失败可重试。正文通过现有 JSON 校验后再事务入库。

每本书保存仓库身份、书籍 ID、来源路径、分支和正文版本。文件移动不重复导入，不同仓库的相同书籍 ID 不相互覆盖。

源标签与个人标签分开保存：

- 更新正文保留个人标签和分组。
- 更新后仍能可靠定位的阅读记录继续保留。
- 无法定位的记录保留并提示处理。
- 远端文件删除不自动删除本地内容。
- 删除本地书籍不影响远端书源。

现有数据库的书籍 ID 唯一约束需要配合来源映射调整，涉及正文引用、阅读锚点和备份的修改必须一起完成。

## 6. 阅读进度双向同步

第一版同步具有 GitHub 来源映射的书籍。同步内容包括：

- 书籍身份和正文版本。
- 章节／诗作、内容 ID、文字偏移及定位上下文。
- 阅读中／已读状态。
- 设备标识、递增序号及已观察到的其他设备版本。

页码和百分比不作为唯一定位或覆盖依据。本地导入书籍不凭标题自动匹配远端书籍。

每台设备写自己的进度文件：

```text
progress/
├─ device-a.json
└─ device-b.json
```

| 场景 | 处理方式 |
| --- | --- |
| B 读取 A 的进度后继续阅读 | 自动采用后续进度 |
| A、B 离线分别阅读同一本书 | 保留候选位置，让用户选择 |
| 同一记录重复上传 | 不重复应用 |
| 设备时间不一致 | 不单凭时间决定覆盖 |
| 另一设备尚未下载书籍 | 保存进度，下载后继续阅读 |
| 正文版本发生变化 | 尝试稳定定位，失败则提示选择章节 |
| 网络或授权失败 | 本地继续阅读，保留待同步记录 |

冲突选择结果也生成新版本，避免同一个冲突反复出现。远端更新失败后重新读取、合并并有限重试，不盲目覆盖。

同步时机：

- 打开 App、进入书籍时读取远端。
- 阅读时立即本地保存，合并多次变化后上传。
- 离开阅读页安排同步。
- 提供手动同步与联网后台补偿。

恢复旧备份后先暂停自动上传，与远端比较后再继续，避免旧进度覆盖其他设备的新进度。

## 7. 单独标注：登录 GitHub 的优势

| 登录优势 | 对用户的价值 |
| --- | --- |
| 访问私有书源 | 书籍无需公开 |
| 选择已授权仓库 | 减少手动输入，同时保留手动修改 |
| 使用认证请求配额 | 减少匿名访问限流影响 |
| 写入私有进度仓库 | 多设备接续阅读 |
| 显示实际账号身份 | 便于切换和排查权限问题 |
| 管理授权状态 | 支持退出、重新授权和授权失效提示 |

公开书源允许不登录浏览。登录不会获得书源管理功能，也不会自动开启进度同步。

正式登录流程、权限隔离和令牌生命周期必须完成实现；手动令牌配置只能作为备选，不能代替登录功能验收。凭据不写入日志、书库备份或同步文件，不把应用密钥打包进 APK。

## 8. 开发安排：全部完成后再测试

### A. 全部功能开发

依次完成：

1. 索引、来源映射、进度协议和授权配置设计。
2. GitHub 登录、权限隔离、账号与仓库手动切换。
3. 数据库迁移、来源关联、标签区分和备份兼容。
4. 索引生成工具、目录浏览、解析与缓存。
5. 下载队列、取消、重试、更新与入库。
6. 进度同步、冲突处理、后台补偿。
7. 全部页面、状态提示、备份恢复协调和使用说明。
8. 配套测试代码与测试数据编写。

**此阶段不运行功能测试。** 允许静态代码审阅和必要的编译打包，用于发现语法或链接问题；不执行单元测试、仪器测试、Lint、Schema 检查、手动功能测试或真实账号同步试验。

进入测试的条件：

- 全部功能已有实际实现。
- 无占位页面、模拟成功或未接通接口。
- 必需的授权注册配置已准备。
- 应用与测试包能够构建。

### B. 统一测试

全部开发完成后，集中执行：

1. 协议、来源身份与数据库测试。
2. 登录、权限及账号／仓库切换测试。
3. 目录、索引、下载与更新测试。
4. 双设备顺序阅读及离线冲突测试。
5. 网络故障、授权失效和备份恢复测试。
6. 现有阅读、标签、分组、导入与备份回归。

测试发现问题后修复并运行相关回归；不重复执行无关测试。编译成功不能代替功能验收。

### C. 交付

交付新版 APK、源码包、索引示例与生成工具、连接配置说明，以及记录实际结果的验收报告。

## 9. 关键验收标准

- App 无远端书源写入能力。
- 用户可自行更换登录账号、仓库所有者、仓库、分支和目录。
- 切换失败不破坏旧连接，切换成功不混用旧缓存或请求。
- 不同仓库的相同书籍 ID 不相互覆盖。
- 中文多级目录、批量下载及正文更新可用。
- 两台设备可接续阅读，离线冲突不静默丢失。
- 旧书库升级后保留，凭据不随普通备份导出。
- 所有测试均在全部功能开发完成后启动。
