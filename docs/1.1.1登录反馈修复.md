# 1.1.1 登录反馈修复

日期：2026-11-01。

## 修改

- 点击“登录 / 更换账号”后立即显示“正在连接 GitHub，获取登录设备码”。
- 已有请求进行中时显示忙碌状态和提示，不再静默忽略重复点击。
- 等待用户授权时显示明确的等待状态。
- 连接超时、DNS 失败、安全连接失败和网络连接失败显示相应说明；失败后解除忙碌状态，允许重试。
- GitHub 返回已识别的 OAuth 错误时，说明 Device Flow 未启用、Client ID 无效、授权取消或设备码过期。

## 已验证

构建成功，覆盖安装成功。RemoteConnectionTest 三项通过，3.093 秒：

1. 手动修改连接后取消，不保存修改。
2. 控制后台请求保持等待，验证即时状态显示和重复点击登录时的忙碌反馈。
3. 注入连接超时，验证错误原因显示和失败后重试可完成。

本轮测试使用可控制的后台任务，不请求真实账号授权，不代表 GitHub 设备码和授权链路已联调通过。Lint 报告见 artifacts/verification/1.1.1/lint.txt。

## 手机验证步骤

1. 覆盖安装 QuietReader-1.1.1-debug.apk，进入“更多 → GitHub 书库与进度同步 → 书源账号与仓库设置”。
2. 点击登录，立即应看到连接提示。连续点击应提示已有请求，不应无反馈。
3. 正常网络下应出现设备码；若失败，记录提示全文。特别核对手机浏览器能否访问 github.com，以及 GitHub App 是否启用 Device Flow。
4. 在浏览器输入设备码并授权，返回 App 点击“我已授权，等待确认”，应显示等待状态，完成后显示实际账号。
5. 断网点击登录，最终应提示连接失败；恢复网络并关闭提示后可以重新点击，不应一直处于忙碌状态。
6. 对进度账号重复以上流程，确认两套登录账号与连接配置独立。

只需反馈具体失败提示和所在步骤，不要发送访问令牌或密钥。
