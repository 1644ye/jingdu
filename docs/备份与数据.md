# 备份与数据

本文对应 `LibraryStore`、`MainActivity` 和协议版本 1 的实际实现。内容导出、完整备份和 SQLite 数据库版本是三个独立概念，不能互相改名替代。

## 两种 JSON 文件

| 文件 | `kind` | `schemaVersion` | 用途 |
|---|---|---|---|
| 内容文件 | `ebook-library` | 数字 `1` | 一至多本诗集或小说的正文和元数据；不包含用户阅读记录 |
| 完整备份 | `ebook-backup` | 数字 `1` | 全部内容、阅读状态、位置、笔记、分组、收藏和已保存的阅读设置 |

普通内容文件的 `books` 必须非空，单文件最多 1000 本。完整备份的 `content.books` 可以为空，因而空书库也能备份和恢复。完整备份逐本使用相同的内容规则校验，不套用普通内容文件的“至少一本、最多 1000 本”总量规则；其总量受备份文件、节点和记录数量上限限制。

机器可检验的结构定义位于：

- `core/src/main/resources/protocol/ebook-library-v1.schema.json`
- `core/src/main/resources/protocol/ebook-backup-v1.schema.json`

备份 Schema 是自包含的 JSON Schema Draft 2020-12 文件，内嵌了诗集与小说的定义，校验时不需要下载其他 Schema。它检查结构、必填项、字段类型、枚举、整数范围及部分数组数量；应用的 Kotlin 校验器是运行时实现，仍需执行下面列出的语义校验。

## 完整备份结构

以下是有效的空书库备份。根字段均必填，即使没有对应数据也应保留空数组或空对象。

```json
{
  "schemaVersion": 1,
  "kind": "ebook-backup",
  "createdAt": 0,
  "content": { "schemaVersion": 1, "kind": "ebook-library", "books": [] },
  "library": [],
  "groups": [],
  "memberships": [],
  "positions": [],
  "annotations": [],
  "poemFavorites": [],
  "settings": [],
  "metadata": {}
}
```

时间使用非负的 Unix 毫秒整数。时间值、分组 ID 和记录 ID 的存储范围不超过有符号 64 位整数上限 `9223372036854775807`；ID 必须大于零。处理这些整数的外部工具应避免浮点数舍入，应用会检查能否精确转换为整数。

| 字段 | 内容与规则 |
|---|---|
| `createdAt` | 生成备份时的 Unix 毫秒时间 |
| `content` | `schemaVersion: 1`、`kind: ebook-library` 和 `books`；每本书保留协议中的稳定 ID、数组顺序及已接受字段 |
| `library` | 每本书恰好一条状态记录；不能缺失，也不能引用不存在的书 |
| `groups` | 个人分组，`id` 为正整数，`name` 为非空字符串；ID 和名称各自唯一 |
| `memberships` | `{ "bookId": "…", "groupId": 1 }`；书和组必须存在，同一关系不能重复；一本书可关联多个组 |
| `positions` | `{ "anchor": {…}, "progress": 0.5 }`；每本书最多一条，`progress` 为 0 至 1 |
| `annotations` | 书签、划线与笔记记录，结构见下文 |
| `poemFavorites` | `{ "bookId": "…", "poemId": "…" }`；必须引用真实诗集中的诗作，同一收藏不能重复 |
| `settings` | `{ "scope": "", "settings": {…} }`；空 `scope` 表示全局，书籍 ID 表示该书覆盖；每个范围最多一条 |
| `metadata` | 值均为字符串的键值对象；当前使用 `examples_initialized` 记录内置示例是否已初始化 |

`library` 的每条记录必须包含：

```json
{
  "bookId": "book-novel-demo",
  "favorite": false,
  "status": "reading",
  "progress": 0.5,
  "lastRead": 1793000000000,
  "importedAt": 1792900000000,
  "revision": 1
}
```

`status` 只接受 `unread`、`reading`、`read`。`favorite` 必须是 JSON 布尔值。`revision` 是内容修订号，范围为 1 至 `2147483647`；内容更新时增加，供阅读器识别正文缓存是否需要刷新。`progress` 为 0 至 1，若存在对应 `positions` 记录，两处进度的差不能超过 `0.00001`。

## 稳定位置、书签、划线与笔记

所有位置使用同一种 `anchor`：

```json
{
  "bookId": "book-novel-demo",
  "sectionId": "chapter-1",
  "contentId": "block-1",
  "start": 0,
  "end": 2,
  "quote": "雨停",
  "prefix": "",
  "suffix": "的时候，一封没有署名的信送到了旧书店。",
  "orphaned": false
}
```

`sectionId` 是章节或诗作 ID，`contentId` 是小说正文块或诗行 ID。`start`、`end` 使用 **UTF-16 单元偏移**，结束位置不包含在选区内，与 Android 文本选择和排版 API 一致；不能把 Unicode 码点数或 UTF-8 字节数当作偏移。

全部九个字段必填；`quote`、`prefix`、`suffix` 允许空字符串，`orphaned` 必须是布尔值。偏移必须满足 `0 <= start <= end <= 2147483647`。

- `orphaned: false`：书、篇章和正文必须存在；偏移不得越界，原文 `[start, end)` 必须与 `quote` 完全一致。
- `orphaned: true`：书仍须存在，但允许原篇章或正文已删除或变化。应用保留记录及笔记，并显示“原位置已变化”。不会自动绑定到别的内容 ID。
- 正常保存新记录时会检查选区不截断 UTF-16 代理对。自动生成的短摘录和前后文也会避开代理对边界。备份语义校验检查偏移及摘录一致性，不把 Schema 当作文本边界检查器。
- 内容更新时先读取旧锚点对应正文，再调用 `Anchors.relocate`。只在同一本书、同一篇章、同一内容 ID 内重新定位；文本不变时保持位置，文本变化时使用摘录及前后文判断，缺失或不唯一时标记失效。已有失效记录不会自动恢复。

`annotations` 每条记录的形状如下。`id` 唯一，`kind` 只允许 `bookmark`、`highlight`、`note`，`note` 即使为空也必须提供。

```json
{
  "id": 1,
  "anchor": {
    "bookId": "book-novel-demo", "sectionId": "chapter-1", "contentId": "block-1",
    "start": 0, "end": 2, "quote": "雨停", "prefix": "", "suffix": "的时候，", "orphaned": false
  },
  "kind": "note",
  "note": "留意这段开场。",
  "createdAt": 1793000000000
}
```

## 阅读设置

每条 `settings[].settings` 都是完整设置对象，原有字段必填。1.0.1 增加的三个自定义颜色字段为可选，以兼容旧备份；省略时使用下表默认值。当前没有显式存储的全局或单书设置不会额外生成备份记录；恢复后仍使用应用默认值或继承全局设置。单书覆盖保存完整设置快照，删除该覆盖后重新继承全局。

| 字段 | 类型与范围 | 当前默认 |
|---|---|---|
| `mode` | `scroll`、`paged`，兼容 `page` 别名 | `scroll` |
| `fontSize` | 数值 12–64 | 22 |
| `lineSpacing` | 数值 1–3 | 1.5 |
| `paragraphSpacing` | 数值 0–80 | 16 |
| `margin` | 数值 0–120 | 24 |
| `fontFamily` | 非空字体族字符串，最多 256 个 UTF-16 单元 | `serif` |
| `theme` | `system`、`light`、`sepia`、`dark`、`custom` | `system` |
| `customBackground` | 可选，`#RRGGBB` 六位十六进制背景色 | `#F8F6F0` |
| `customSurface` | 可选，`#RRGGBB` 六位十六进制卡片色 | `#FFFDF7` |
| `customAccent` | 可选，`#RRGGBB` 六位十六进制按钮色 | `#416752` |
| `keepAwake` | 布尔值 | `false` |
| `indent` | 布尔值 | `true` |
| `showOriginal` | 布尔值 | `true` |
| `showPinyin`、`showTranslation`、`showNotes`、`showAnalysis` | 各自为布尔值 | 均为 `false` |

界面滑杆可调范围可能比持久化协议范围窄。JSON 不接受字符串形式的数字、`null`、非有限数值或缺失布尔字段。字体族是否在目标设备可用不由备份校验器验证，Android 字体系统可回退到可用字体。

`custom` 主题使用上述三个自定义色值，正文与按钮文字由各自背景自动计算为黑色或白色；其他主题保留色值以供再次启用。颜色从“更多 → 应用配色”保存到全局设置，单书覆盖仍以本书快照为准。1.0.1 可读取旧版设置与备份；使用 `custom` 的新备份不承诺可由1.0.0读取，旧版会拒绝不认识的主题，恢复时请使用1.0.1或更新版本。

## 恢复流程和失败保护

1. 从系统文件选择器读取 UTF-8 JSON，兼容 BOM；严格解析，拒绝重复对象字段和尾随内容。先检查文件大小、嵌套深度、节点数。
2. `validateBackup` 检查版本、字段类型、内容协议、所有关联关系、重复 ID、阅读设置、锚点及进度一致性。应用显示书籍、阅读记录、分组数量，并提示整体替换。
3. 用户确认后，`restoreBackup` 再校验一次输入，并取得当前数据库快照；也校验该快照确实可用于恢复。
4. 将当前快照写入应用内部 `filesDir/recovery/` 的临时文件，刷新写入缓冲并调用文件描述符 `sync()`，再重命名为 `before-restore-时间戳-随机后缀.json`。任何一步失败均不开始替换数据库。
5. 在一个 SQLite 事务中清除旧书库、分组、设置与元数据，并写入新内容及全部关系、位置、笔记和设置。书籍和记录的备份 ID 保留。
6. 执行 `PRAGMA foreign_key_check`，无异常才提交。失败则整个事务回滚，保留原数据和已生成的保护备份。

恢复采用整体替换，不是与现有库合并。恢复写入阶段没有取消入口，避免对提交结果产生误解；恢复前的读取和校验阶段可以取消。保护备份可在恢复成功弹窗中导出，也可以后通过“更多 → 备份与恢复 → 导出恢复前保护备份”选择并导出。

应用内部保护备份不是异地备份，卸载应用会删除它；需要保留时应导出到用户选择的位置。恢复后的 `examples_initialized` 会设为 `"1"`，防止空库恢复后再次自动插入示例。备份中的未知字段允许通过结构校验，但恢复只承诺当前已定义字段；内容内部的未知字段按内容协议清理，不作为可靠备份扩展机制。

## SQLite 存储与迁移

默认数据库名为 `quiet-reader.db`，当前 `SQLiteOpenHelper` 数据库版本为 **3**。数据库启用外键、WAL 和 5000 ms busy timeout。应用通过一个 `LibraryStore` 实例访问数据库；方法同步执行并以实例锁互斥，调用者必须在后台线程调度耗时操作。互斥本身不保证不同后台队列的业务先后顺序，调用者仍须协调暂停保存和后续恢复等操作。

| 表 | 保存内容与关联 |
|---|---|
| `books` | 稳定书籍 ID、元数据、收藏、阅读状态、进度、时间及内容修订号 |
| `sections` | 每章或每首诗的 JSON、顺序、标题、卷 ID 和卷名；复合主键为书籍 ID + 篇章 ID；目录按卷 ID 分组，同名的不同卷仍独立 |
| `texts` | 可定位的诗行或正文块原文和顺序；按书籍内内容 ID 唯一 |
| `positions` | 每本书的最近锚点和进度 |
| `annotations` | 书签、划线及笔记；只外键关联书籍，不能因替换篇章而级联删除 |
| `shelf_groups`、`memberships` | 分组及书籍与分组的多对多关系 |
| `poem_favorites` | 诗作收藏，关联实际篇章 |
| `settings` | 全局或单书完整设置对象 |
| `metadata` | 示例初始化等内部状态 |

正文按篇章读取，不需要打开整本书 JSON 才能阅读。全文搜索使用后台 SQLite `LIKE` 筛选与 Kotlin 字符串查找，按原文 ID 和偏移返回中文子串命中；它不是中文分词索引。`book()` 仅用于组装完整内容导出。

版本 1 → 2 的迁移会给 `books` 新增 `content_revision INTEGER NOT NULL DEFAULT 1`，并创建篇章顺序、正文顺序、笔记和分组关系索引。版本 2 → 3 给 `sections` 新增 `volume_id TEXT NOT NULL DEFAULT ''`，逐章从已有 JSON 的 `volumeId` 回填，不需要加载整本书正文；诗作和不分卷章节保留空字符串。这样目录读取只查询轻量列，也能区分同名的不同卷。

从版本 1 直接升级到 3 时顺序执行这两步。`SQLiteOpenHelper` 在事务中执行迁移；异常向上传递，不清库、不重建成空数据库。数据库版本高于应用支持版本时明确拒绝降级。首次安装直接创建版本 3；后续版本必须新增显式迁移，不能以删除数据库代替迁移。备份协议仍为版本 1，因为章节已有 `volumeId`，新列属于可从正文重建的存储索引信息。

内容更新对 `books` 执行更新并增加修订号，替换该书的 `sections/texts`。笔记和位置保留并重定位；诗作收藏因篇章外键会暂时级联删除，更新代码会恢复其中仍存在的同 ID 诗作。删除整本书才会删除其关联的阅读记录、分组归属、诗作收藏及单书设置。

每个导入文件独立事务，任何书籍校验或写入失败都回滚该文件。取消会保留此前已经提交的文件，回滚当前文件；进度回调之后、事务提交之前仍有一次取消检查。已有书籍默认跳过；副本会重建书籍及全部内部 ID 和卷引用，不继承原书私人阅读记录。

## 实际数据上限

大小单位按二进制计算：1 KiB = 1024 字节，1 MiB = 1024 × 1024 字节。

| 对象 | 上限及检查位置 |
|---|---|
| 普通内容文件 | UTF-8 32 MiB；单批最多 16 文件、累计 64 MiB，文件选择与解析流程检查 |
| 普通 JSON 内容树 | 嵌套 32 层、100 万 JSON 值节点；单文本最多 400 万 UTF-16 单元；运行时协议检查 |
| 内容数量 | 单文件 1000 本；单书 10000 首诗或章节；单书内部内容 ID 总量 20 万；标签数组 1000 项 |
| 一章或一首诗 | 清理后的紧凑 JSON UTF-8 序列化不超过 1 MiB；导入和恢复检查，避免超大 SQLite CursorWindow 行 |
| 一本书的元数据 | 移除 `poems`/`chapters` 后的 JSON UTF-8 不超过 256 KiB，包括卷目录；导入、编辑和恢复检查 |
| 一条笔记正文 | UTF-8 不超过 128 KiB；新建、修改和恢复检查 |
| 完整备份文件 | 用户导入和导出入口为 128 MiB；导出超过限制会失败并提示目标文件可能不完整 |
| 完整备份树 | 嵌套 48 层、300 万 JSON 值节点；解析和恢复校验均检查 |
| 备份顶层记录数组 | `library`、`groups`、`memberships`、`positions`、`annotations`、`poemFavorites`、`settings` 各最多 500000 项 |

内部自动生成保护备份使用应用私有文件写入，不经过用户文件选择器的 128 MiB 输出包装器；它仍须通过备份语义校验。实际累积书库超过用户可恢复的备份文件上限时，不应依赖该文件作为唯一备份策略，应先减少库大小并重新导出可验证的完整备份。

上述是格式与数据量的硬上限，不保证每台设备均能处理到该大小。文件读取还根据应用最大堆、当前可用堆和保留空间估算UTF-16缓冲/解析所需内存，预算不足会在写入前明确拒绝。完整备份仍组装为内存JSON树；接近上限的大书库、低内存设备和极端资源不足尚未做完整压力验证。

Schema 无法单独确认 ID 唯一性、跨表引用、锚点文本相等、按 UTF-16 计数、JSON 树总节点数或 UTF-8 序列化字节数。这些属于 `Protocol.validate` / `LibraryStore.validateBackup` 的语义与资源限制。通过 Schema 不等于可以安全恢复；不要跳过应用验证直接写数据库。

## 验证范围

数据库测试位于 `app/src/androidTest/java/org/quietreader/data/LibraryStoreTest.kt`，覆盖逐文件失败和取消回滚、重复导入、副本引用、更新失效、取消更新恢复关联关系、搜索、备份恢复、恢复注入失败、损坏备份拒绝、示例初始化、迁移和降级保护。

`PerformanceTest` 在独立测试数据库内生成 1000 首诗、1000 章且恰好 300 万中文字符的小说、10 本书批次，记录数据层阶段耗时和内存观测。它不证明界面翻页、首帧或触控性能；设备实际执行结果及未验证事项以项目验收报告为准。
