# 1.1.2 仓库连接错误修复

日期：2026-11-01。

用户在只读书源连接页面遇到“远端版本发生变化，请重新同步”。代码将读取请求的 409/422 一律映射为写入版本冲突，且连接书源时要求已存在提交，导致空仓库无法正常保存连接。

## 修复

- 保留 GitHub 错误响应中的有限长度 message，区分 GitHub 明确报告的空仓库与其他读取冲突。
- GitHub 明确返回空仓库时，允许保存连接，提示先在 GitHub 上传书籍 JSON 和 catalog.json；App 不向书源写入文件。
- 浏览空仓库时给出缺少首次提交及书籍索引的说明。
- 无法读取指定分支时显示分支名称、HTTP 状态和检查权限/首次提交的说明，不再要求重新同步。
- 只有 PUT 写入的 409 冲突才提示远端版本变化。422 不再被统一解释为版本冲突。
- 空进度仓库的首次同步跳过读取不存在的进度目录和文件，直接创建本设备进度文件；不存在的分支不再当作空仓库吞掉。

## 验证

构建与 Lint 成功。GitHubRepositoryTest 5 项和 RemoteConnectionTest 3 项通过，共 8 项，2.754 秒。API 测试使用固定响应，覆盖空仓库识别、正常提交、缺失分支、其他冲突不误判为空仓库、写入冲突提示，以及上一版连接反馈回归。

进度仓库首次写入的调用处理在上述测试后补齐，并重新编译检查。实际私有仓库连接与首次写入仍需手机授权后验证，不能以固定响应测试替代。

## 手机复测

1. 覆盖安装 QuietReader-1.1.2-debug.apk，在原页面再次点击“连接并保存”，分支留空以使用默认分支。
2. 空仓库应提示“连接已保存，仓库暂无提交”。随后在 GitHub 网页或电脑上传书籍和 catalog.json，再回 App 刷新。
3. 若仓库已有内容仍失败，记录新版本显示的完整错误和分支名称，检查该 GitHub App 的 Contents 读取权限及安装范围。
4. 私有 reading-state 连接保存后，启用同步并手动同步，验证首次创建 progress/设备ID.json。

截图本身不能确认用户仓库确实为空；当前修复针对已确认的错误映射与空仓库处理缺陷。
